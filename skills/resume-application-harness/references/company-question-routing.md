# 회사별 문항 분석·분량·경험 배정

## 원칙

회사마다 묻는 내용과 최소·최대 분량이 다르다. 고정 자기소개서를 회사명만 바꿔 쓰지 않는다. 원문 문항, 공고, 직무, 글자 계산 단위를 먼저 분석하고 필요한 경험만 골라 재구성한다.

## 문항 원문에서 추출할 항목

```yaml
question:
  raw_text:
  company:
  role:
  minimum_length:
  maximum_length:
  counting_unit: characters | characters_without_spaces | utf8_bytes | words | unknown
  spaces_included: true | false | unknown
  line_break_rule: counted | not_counted | unknown
  mandatory_subparts: []
  intent_labels: []
  company_keywords: []
  job_keywords: []
  value_keywords: []
  evidence_requested: []
  required_experience_count:
  blind_recruitment_rules: []
  prohibited_content: []
  unanswered_slots: []
```

공고와 입력창에 규칙이 다르면 입력창을 우선하되 사용자가 직접 확인할 수 있게 차이를 알린다.

## 복합 문항 분해

다음 표현 뒤의 내용을 별도 필수 슬롯으로 본다.

- `및`, `그리고`, `각각`
- `포함하여`, `바탕으로`, `연결하여`
- `구체적으로`, `근거와 함께`, `사례를 들어`
- `본인의 역할`, `행동`, `결과`, `배운 점`
- `입사 후 활용`, `향후 계획`, `기여 방안`
- `왜`, `어떻게`, `무엇을`

예:

> 지원동기와 직무 적합성, 입사 후 목표를 구체적인 근거와 함께 작성해 주십시오.

필수 슬롯:

1. 회사 지원 이유
2. 직무 지원 이유
3. 적합성 주장
4. 이를 뒷받침하는 경험·기술
5. 입사 후 목표
6. 실행 방법

초안 뒤에 각 슬롯이 실제 문장으로 들어갔는지 확인한다. 키워드만 등장했다고 충족으로 보지 않는다.

## 문항 유형별 의도와 필요한 카드

### 지원동기·회사 선택

평가하려는 것:

- 회사와 직무를 구분해 이해했는지
- 다른 회사에도 붙는 칭찬이 아니라 실제 선택 이유가 있는지
- 본인의 과거 경험과 선택이 이어지는지

필요 슬롯:

1. 본인의 회사·직무 선택 기준
2. 공고·제품·서비스·사업에서 확인한 구체적 사실
3. 관심이 생긴 개인 경험
4. 이미 준비하거나 해 본 행동

추가 질문은 `회사 칭찬을 모두 빼면 남는 이유가 무엇인지`에 집중한다. 최신 회사 사실은 공식 공고와 공식 자료로 확인한다.

### 직무역량·전문성·적합성

평가하려는 것:

- 실제 업무를 수행할 지식·기술·태도가 있는지
- 교육·자격 이름이 아니라 적용 장면이 있는지
- 숙련 범위를 정확히 말하는지

필요 슬롯:

1. 할 수 있는 실제 업무
2. 배운 경로
3. 적용 경험
4. 사용 도구와 독립 수행 범위
5. 결과 또는 결과물
6. 부족한 부분과 보완 계획

### 성취·목표 달성

평가하려는 것:

- 목표와 결과가 분명한지
- 장애물에서 본인이 한 행동이 무엇인지
- 팀 성과와 개인 기여가 구분되는지

필요 슬롯: 목표, 시작 상태, 장애물, 본인 행동, 결과, 근거.

### 도전·변화·혁신

평가하려는 것:

- 새로웠던 점과 위험을 이해했는지
- 기존 방식이 안 된 이유를 판단했는지
- 실패 후 수정하고 정착시켰는지

필요 슬롯: 기존 방식, 변화 필요, 위험·반대, 시도, 수정, 정착 결과.

### 실패·실수·위기

평가하려는 것:

- 실패를 솔직히 인정하는지
- 자기 책임과 외부 요인을 구분하는지
- 수습과 재발 방지가 행동으로 남았는지

필요 슬롯: 기대와 실제 결과, 본인 책임, 즉시 수습, 원인 확인, 재발 방지, 이후 행동 변화.

실패를 억지 성공담으로 만들지 않는다. 기대와 실제 결과의 차이와 본인 책임이 확인되지 않으면 경험을 `미배정`으로 두고 초안을 만들지 않는다. 결과가 좋지 않았어도 수습과 행동 변화가 분명하면 답이 된다.

### 문제해결·개선

평가하려는 것:

- 현상과 원인을 구분했는지
- 자료를 확인하고 대안을 비교했는지
- 해결 여부와 재발을 검증했는지

필요 슬롯: 현상, 확인 자료, 원인, 대안, 선택 기준, 실행, 검증, 예방.

### 협업·팀워크

평가하려는 것:

- 공동 목표와 역할을 이해했는지
- 정보·일정·업무를 실제로 어떻게 맞췄는지
- 팀 결과와 개인 행동이 모두 보이는지

필요 슬롯: 공동 목표, 각 역할, 협업 필요, 공유·조정 행동, 팀 결과, 개인 기여.

### 갈등·설득·협상

평가하려는 것:

- 상대를 나쁜 사람으로 단순화하지 않는지
- 주장 아래의 이해관계를 파악했는지
- 기준과 자료로 조정했는지

필요 슬롯: 의견 차이, 이해관계, 경청·확인, 근거, 양보·유지한 부분, 합의와 이후 관계.

### 고객·서비스

평가하려는 것:

- 요청 뒤의 실제 불편을 이해했는지
- 규정과 고객 요구를 함께 다뤘는지
- 후속 조치로 문제 종료를 확인했는지

필요 슬롯: 고객과 요청, 실제 불편, 규정·제약, 설명·대안, 후속 확인, 결과.

### 리더십·주도성

평가하려는 것:

- 직책이 아니라 사람과 일을 움직인 행동이 있는지
- 공식 권한의 범위를 정확히 말하는지
- 역할 배분과 진행 확인을 했는지

필요 슬롯: 권한 유무, 공동 목적, 참여를 얻은 방식, 역할 조정, 지원·피드백, 팀 결과, 개인 행동.

직급 번역만으로 사람 관리 경험을 만들지 않는다.

### 윤리·안전·책임

평가하려는 것:

- 빠른 처리나 개인 이익보다 지킨 기준이 있는지
- 위험·오류를 숨기지 않고 보고했는지
- 예방 조치가 남았는지

필요 슬롯: 위험·딜레마, 지킨 규정·기준, 판단 이유, 보고·중지·기록·수정 행동, 영향, 예방.

### 성장과정·가치관

평가하려는 것:

- 현재 행동 원칙이 어떻게 형성됐는지
- 가치관이 실제 업무 행동으로 나타나는지

필요 슬롯: 영향을 준 사건, 형성된 원칙, 최근 적용 사례, 직무에서의 행동.

어린 시절 연대기를 길게 쓰지 않는다. 블라인드 규칙이 있으면 가족·출신 배경을 제외한다.

### 장점·보완점

평가하려는 것:

- 자기평가에 근거가 있는지
- 보완점이 치명적 자기비하가 아니라 실제 개선 행동으로 이어졌는지

장점 슬롯: 장점, 반복해서 나타난 행동, 근거 사례, 직무 관련성.

보완점 슬롯: 실제 문제, 피해를 줄인 습관·도구·절차, 현재 상태, 남은 과제.

### 학습·자기개발·디지털 활용

평가하려는 것:

- 학습 필요를 스스로 찾았는지
- 수강에서 끝나지 않고 적용했는지
- AI·자동화·데이터 사용 시 검증·보안 책임이 있는지

필요 슬롯: 계기, 학습 순서, 자료·도구, 적용 장면, 검증, 결과, 다음 학습.

### 입사 후 포부·직무수행계획

평가하려는 것:

- 실제 직무를 이해하는지
- 지나친 장기 비전보다 현실적인 실행 순서가 있는지

필요 슬롯:

1. 입사 직후 익힐 기준·도구·업무
2. 3개월 안에 할 수 있는 역할
3. 1~3년 뒤 맡을 범위와 필요한 준비
4. 결과를 확인할 상태·지표

확인되지 않은 회사 내부 계획을 만들어 넣지 않는다.

### 공백기·직무전환

평가하려는 것:

- 현재 업무 준비 상태
- 이전 경험에서 이어지는 행동
- 불필요한 사적 설명 없이 전환 이유를 설명하는지

필요 슬롯: 공개 범위, 기간 중 유지·학습, 이전 경험의 이전 가능한 행동, 현재 준비 근거.

### 사회·산업 이슈

평가하려는 것:

- 쟁점을 단순 찬반이 아니라 이해관계와 근거로 보는지
- 직무와의 연결이 현실적인지

필요 슬롯: 쟁점, 이해관계자, 근거, 반대 입장의 타당한 점, 본인 입장, 직무 영향.

### 자유 자기소개

평가하려는 것:

- 다른 문항에서 드러나지 않은 핵심 특징
- 한두 경험으로 설명되는 일관성

필요 슬롯: 한 문장 요약, 근거 경험 1~2개, 직무에서 먼저 쓸 행동.

## 경험 선택 점수

점수는 보조 수단이다. 사실 불확실성이 있으면 적합성보다 먼저 제외한다.

```text
직무 연관성          0~4
문항 의도 적합성     0~3
본인 행동 명확성     0~3
결과·증빙            0~2
최근성                0~1
개인적 구체성        0~1
사실 불확실          -5
같은 지원서 내 중복  -1
```

가장 높은 경험을 기계적으로 고르지 않는다. 문항 전체에서 소재가 겹치지 않는지 보고 배정한다.

## 경험 사용표

```yaml
experience_usage:
  - question_id: Q1
    intent: support_motivation
    card_ids: [EXP-003]
    angle: company_choice_and_relevant_work
  - question_id: Q2
    intent: job_fit
    card_ids: [EXP-001]
    angle: safety_and_daily_checks
```

- 동일 지원서에서 같은 카드 반복을 기본적으로 피한다.
- 경험이 하나뿐이면 반복 사실을 알린다. 같은 카드를 다시 쓰려면 서로 다른 확인 사실, 다른 행동·판단, 사용자 고지라는 세 조건을 모두 지킨다.
- 약한 경험을 새로 꾸며 내는 것보다 솔직한 재사용이 낫다.
- 회사가 달라지면 같은 경험 카드를 재사용할 수 있지만 공고와 문항에 맞게 강조점을 다시 정한다.

## 분량별 기본 구성

다음은 절대 공식이 아니라 첫 초안의 휴리스틱이다.

| 최대 분량 | 기본 구성 | 경험 수 |
|---:|---|---:|
| 200~300자 | 직접 답변 + 행동 근거 하나 + 결과 또는 연결 | 1 |
| 400자 | 경험 하나, 3~5문장 | 1 |
| 500자 | 경험 하나, 짧은 1~2단락 | 1 |
| 700자 | 상황·행동·결과·직무 연결이 가능한 경험 하나 | 1 |
| 1,000자 | 깊은 경험 하나 + 보조 근거 또는 직무 연결 | 1~2 |
| 1,500자 | 경험 두 개 또는 변화 과정을 포함한 복합 경험 | 1~2 |
| 2,000자 이상 | 경험 2~3개 이내, 필수 슬롯을 단락으로 분리 | 2~3 |

운영 원칙:

- 최소 분량이 있으면 반드시 확인한다.
- 최대 분량의 90~96%를 첫 목표로 삼아 입력창 수정 여백을 남긴다. 사실이 부족하면 억지로 채우지 않는다.
- 500자 이하에서는 소제목이 공간을 잡아먹으면 생략한다.
- 복합 문항은 필수 슬롯 수와 중요도에 따라 분량을 배분한다.
- 배경보다 행동에 가장 많은 분량을 준다.
- `배운 점`이 명시되지 않았다면 모든 답을 교훈으로 끝내지 않는다.

## 복합 문항 분량 배분 예

700자 문항이 `지원동기 + 직무 강점 + 입사 후 계획`을 묻는 경우:

- 지원동기 20~25%
- 강점의 근거 경험 50~60%
- 입사 후 계획 20~25%

1,000자 문항이 `실패 + 수습 + 배운 점 + 이후 적용`을 묻는 경우:

- 상황과 실패 20%
- 본인 책임과 수습 35%
- 재발 방지 행동 25%
- 이후 적용 결과 20%

실제 내용의 강도에 따라 바꾸고, 퍼센트를 맞추기 위해 문장을 늘이지 않는다.

## 글자·byte 계산

포털마다 공백과 줄바꿈 계산이 다를 수 있다. 다음 값을 함께 확인한다.

- 공백·줄바꿈 포함 문자 수
- 줄바꿈 제외 문자 수
- 모든 공백 제외 문자 수
- UTF-16 code units
- UTF-8 bytes
- 단어 수

```powershell
node <skill-dir>\scripts\korean_application.mjs count --file <draft.txt> --limit 700 --unit chars
node <skill-dir>\scripts\korean_application.mjs count --file <draft.txt> --limit 1500 --unit utf8-bytes
```

`1,500 bytes`를 `1,500자`로 처리하지 않는다. 계산 단위가 `unknown`이면 여러 값을 보여주고 실제 입력창에서 확인한다. 특수문자·줄바꿈 규칙도 입력창에서 최종 확인한다.

## 자동 문항 라우팅

원문을 UTF-8 텍스트로 저장한 뒤 참고 진단을 실행한다.

```powershell
node <skill-dir>\scripts\korean_application.mjs route-question --file <question.txt>
```

정규식 분류는 복합 문항을 놓칠 수 있다. 도구 결과 뒤에 사람이 필수 슬롯을 다시 확인한다.

## 블라인드·민감정보

공고마다 금지 범위가 다르므로 일반 규칙을 단정하지 않는다. 다음을 공고에서 확인한다.

- 성명, 사진, 성별, 나이, 생년월일
- 출신지, 학교명, 학력 정보
- 가족관계와 가족 직업
- 혼인·임신·건강 정보
- 종교·정치 성향
- 기관명·회사명·전공 기재 허용 여부

블라인드 위험이 있는 표현은 경험 카드에 표시하고 해당 출력에서만 가린다. 사진 포함 한국식 이력서, 일반 민간기업 지원서, 공공기관 블라인드 지원서를 같은 규칙으로 만들지 않는다.

## 최종 문항 충족 검사

각 문항마다 확인한다.

- 질문의 직접 답이 첫 1~2문장에 있는가?
- 필수 하위 질문을 모두 답했는가?
- 본인의 행동이 구체적인가?
- 결과의 범위와 근거가 확인됐는가?
- 회사·직무 연결이 필요한 문항에 실제 연결이 있는가?
- 같은 회사 다른 문항과 경험·문장이 반복되지 않는가?
- 회사명·직무명·제품명이 정확한가?
- 최소·최대 분량과 계산 단위를 지켰는가?
- 블라인드·민감정보 규칙을 지켰는가?
- 면접에서 설명 가능한가?

## 실제 분량이 다양한 이유에 대한 자료

공공·민간 채용 문항에는 300자, 300~400자, 300~700자, 500~1,000자, 700자, 1,000자, 1,500자, 2,000자 등 다양한 제한이 실제로 쓰인다. 따라서 고정 템플릿을 쓰지 않고 문항별 제한을 먼저 읽어야 한다.
