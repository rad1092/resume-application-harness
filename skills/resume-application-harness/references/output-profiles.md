# 출력 유형과 문서 검사

## 먼저 정할 것

한 사람의 사실 원장은 공유하되 출력 규칙은 지원처마다 나눈다. 공고와 입력 화면에 별도 양식이 있으면 그 양식을 우선한다.

### `ko-photo`

일반 국내 민간기업에서 사진 포함 이력서를 요구하거나 허용할 때 사용한다.

- 사진을 요구하지 않으면 자동으로 넣지 않는다.
- 원본 사진은 보존하고 방향을 바로잡은 뒤 EXIF·GPS·기기 정보를 제거한 복사본만 쓴다.
- 주민등록번호 전체, 가족관계, 불필요한 신체 정보는 넣지 않는다.
- 표를 쓰더라도 읽기 순서와 페이지 나눔이 흐트러지지 않게 단순하게 만든다.

### `ko-blind`

공공기관이나 회사 공고가 블라인드 지원을 요구할 때 사용한다.

- 사진과 공고에서 금지한 정보를 제외한다.
- 학교명, 출신지, 가족, 성별·나이 등 금지 범위는 공고마다 다시 확인한다.
- 기관명·회사명·전공이 항상 금지된다고 가정하지 않는다.
- DOCX 안의 미디어, 머리글, 메타데이터에도 가린 정보가 남지 않았는지 확인한다.

### `ko-general`

여러 국내 회사에 변형해 쓰는 기본 이력서·경력기술서·자기소개 원본이다.

- 연락처와 기본정보는 필요한 범위만 둔다.
- 경력은 최근순 또는 직무 관련성이 높은 순으로 일관되게 정한다.
- 각 경력은 공식 직책, 기간, 담당 업무, 확인된 결과를 구분한다.
- 자기소개 원본에는 특정 회사 칭찬이나 회사명 치환 문장을 넣지 않는다.
- 경험 카드를 넓게 보존하되 최종 이력서에는 직무 관련성이 높은 내용만 싣는다.

### `en-ats`

영문 이력서와 ATS용 출력이 명시적으로 필요할 때 사용한다.

- 사진, 생년월일, 성별, 혼인, 급여, 퇴사 사유는 지원 국가·회사에서 명시적으로 요구하지 않는 한 제외한다.
- 한 열, 표준 섹션명, 선택 가능한 텍스트, 단순 글머리표를 쓴다.
- 연락처를 머리글·바닥글·텍스트 상자에 숨기지 않는다.
- 장식 그래픽, 기능 막대, 단어 대신 쓰는 아이콘, 복잡한 표와 다단을 피한다.
- 직급 번역이 사람 관리·예산 권한을 암시하지 않는지 확인한다.

### `job-targeted`

해당 지원처에 맞는 기본 유형을 상속한다.

- 공고에서 확인한 업무·역량에 맞춰 경험의 순서와 강조점을 바꾼다.
- 공고의 키워드를 새 경험으로 만들지 않는다.
- 학습만 한 내용, 근무 가능 조건, 현재 부족한 점을 경험과 구분한다.
- 회사별 자기소개 문항, 첨부 파일명, 용량, 형식을 각각 확인한다.

## 한국어 이력서 기본 구성

공고에 지정 양식이 없을 때 다음에서 필요한 항목만 고른다.

1. 이름과 연락처
2. 한 줄 직무 요약 또는 지원 분야
3. 경력: 회사·기간·공식 직책·담당 업무·주요 결과
4. 프로젝트·경험: 본인 역할·행동·결과
5. 학력
6. 교육·자격
7. 실제 사용 범위가 확인된 도구·기술·외국어
8. 포트폴리오 링크

불필요하게 모든 항목을 채우지 않는다. `성실함`, `책임감`을 기술 목록처럼 적기보다 경력 문장에서 행동으로 보여준다.

## 자기소개서 출력

회사별로 다음을 함께 보관한다.

- 문항 원문
- 최소·최대 분량과 단위
- 문항 의도와 필수 슬롯
- 사용한 경험 카드
- 최종 답변
- 사실 확인 필요 항목
- 공백 포함·제외 글자와 byte
- 예상 면접 꼬리질문

지원서에 올릴 파일에는 내부 카드 ID, 사실 원장, 검사 보고서를 넣지 않는다.

## DOCX 검사

- 문서 속성의 작성자·마지막 수정자·회사명, 주석, 변경 내용 추적, 숨은 글자, 머리글·바닥글, 하이퍼링크, 첨부 개체, 내부 경로를 확인한다.
- 한글에는 동아시아 글꼴을 명시한다.
- 사진 수가 출력 유형과 맞는지 확인한다.
- 마지막 저장 뒤 텍스트를 추출해 최종 초안과 비교한다.
- 현재 실행 폴더에 저장하고 기존 또는 사용자가 이름을 바꾼 파일을 덮어쓰지 않는다.

## PDF 검사

- 페이지 수, 선택 가능한 텍스트, 읽기 순서, 링크, 용량, 메타데이터, 글꼴, 깨진 한글을 확인한다.
- 모든 페이지를 PNG로 렌더링해 100% 크기로 본다.
- 잘림, 겹침, 지나친 공백, 제목만 다음 페이지에 남는 현상, 줄바꿈, 여백, 페이지 나눔을 확인한다.
- DOCX와 PDF에서 추출한 핵심 문장이 같은지 확인한다.

## 사진 검사

- EXIF 방향을 먼저 적용하고 메타데이터를 제거한다.
- RGB JPEG 또는 PNG로 저장한다.
- 원본 사진은 수정하지 않는다.
- 정리한 복사본은 `ko-photo`에서만 쓴다.

## 파일 분리

`publish/`에는 실제로 업로드할 파일만 둔다. 다음은 내부 또는 QA 폴더에 둔다.

- 원본 이력서와 공고 스냅숏
- 경험 카드와 사실·표현 원장
- 문항 분석표와 경험 사용표
- 문체·분량 검사 보고서
- ATS 원본 보고서
- 학습 자료와 면접 메모
- 렌더링한 QA 이미지

## 참고 자료

- [고용24 이력서·자소서 작성 가이드](https://www.work24.go.kr/wk/r/d/1111/resumeSelfIntroGuide2.do): 직무·기업 이해, 실제 경험, 구체성, 진실성, 가독성.
- [Greenhouse 문서 파싱 안내](https://support.greenhouse.io/hc/en-us/articles/200989175-Unsuccessful-resume-parse): ATS 문서의 그래픽, 사진, 복잡한 표, 머리글·바닥글, 텍스트 상자, 다단과 파일 크기 위험. 영문 ATS 출력에만 참고한다.
- [JSON Resume](https://jsonresume.org/): 영문 이력서의 선택적 교환·진단 형식이며 지원자 사실의 출처가 아니다.
